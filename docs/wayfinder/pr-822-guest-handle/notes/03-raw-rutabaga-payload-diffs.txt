##################### 3391f3c5 rutabaga_gfx: cross_domain: support creating guest resources with handles
commit 3391f3c5e87b4f45e64b0931e9036aaa8ec3c3e3
Author: Val Packett <val@invisiblethingslab.com>
Date:   Thu Aug 27 00:08:31 2026 -0300

    rutabaga_gfx: cross_domain: support creating guest resources with handles
    
    With CREATE_GUEST_HANDLE, supporting VMMs/vhosts can share guest memory
    between processes as OS handles (DMA-BUF on Linux). cross-domain's
    context_create_blob already supports guest blobs with handles, but that
    path is only taken for resources created from scratch by a virtio-gpu
    client such as a Wayland proxy. That can be useful as an alternative
    to HOST_VISIBLE virtio SHM, but is not the most exciting use case.
    
    The guest can also *import* DMA-BUFs from other devices, whether udmabuf
    (for zero-copy sharing of memfds) or PCIe-passed-through physical GPUs.
    In that case, the guest userspace has no way of passing in a requirements
    item ID, and the guest kernel does not pass a context ID either. So we
    have to process those resources in the cross-domain *component*.
    
    Signed-off-by: Val Packett <val@invisiblethingslab.com>
