libkrun: remove exec/env/workdir/rlimits support from non-nitro builds

These APIs are no longer needed outside aws-nitro -- non-nitro callers
now configure workloads via Config::apply() with .krun_config.json,
introduced in earlier init-blob commits.

Keep the real implementations behind cfg(feature = "aws-nitro") and
export -ENOTSUP stubs for non-nitro builds so libkrun.so.2 retains the
symbols. Move exec_path, args, env, workdir, rlimits and
console_output out of ContextConfig into a NitroConfig struct gated
the same way.

With these fields gone from the default path, krun_start_enter() no
longer injects them into the kernel command line -- it now only passes
DEFAULT_KERNEL_CMDLINE, block root, and any extra_kernel_cmdline
arguments.

===================== commit 7f7bc099
7f7bc099357794480fb5e426d06962eca493a247
2026-06-04
init-blob: add ffier-based init config library

Add two crates that together produce libkrun-init — a standalone
shared library for building init configurations with a C FFI:

- init-blob: Config/Builder types with #[ffier::export] (gated behind
  an "ffi" Cargo feature). Uses ffier v0.2 library_definition! and
  generate_bridge!(local=...) to emit extern "C" symbols inline.
  Serializes to an internal JSON format matching what the Rust init
  binary parses. Supports parsing OCI runtime-spec config.json via
  Builder::from_oci_json(). ConfigError/ApplyError with FfiError
  derive for proper error handling across FFI.
  crate-type = ["lib", "cdylib"] so it produces both libkrun_init.rlib
  and libkrun_init.so.

- init-blob-via-cdylib: Rust client for the libkrun_init.so C ABI.
  Commits the ffier JSON schema and generates the Rust bindings at
  compile time via ffier-gen-rust-client in build.rs. Used by tests,
  examples, and downstream Rust consumers.

All crates live under init/ alongside the PID-1 binary.

Uses library_tag = 2 (reserving 1 for libkrun) and
primitives_prefix = "krun" so KrunStr/KrunBytes are shared.

Makefile: gen-init-blob-bindings regenerates the JSON schema and
committed C header (SONAME 0 install + pkg-config) using
ffier-gen-c-header. Rust client bindings are not checked in. Build
targets explicitly pass --features ffi to krun-init-blob.
