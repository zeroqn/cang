## Resolution

**Resolved by a tool-capable research child (2026-09-27).** Deliverable:
`../notes/11-pr865-840-matrix.md` plus 14 raw `11-raw-*` evidence files. Heads
were fetched read-only as `refs/remotes/upstream/pr-865` / `pr-840`; the worktree
was not touched.

**Both PRs apply cleanly, in order, onto upstream `main`** (all seven commits
cherry-pick with rc=0; composite `merge-tree` clean; no commit of either PR is
already in main). The committed sequences, now replayed on `cang-main-rebase`:

- **865** (virtio/blk opt-in parallel reads): `802c9e1e` (RwLock for disk image
  access) -> `6b24d0d2` (dispatch reads to a thread pool, fix #824) ->
  `08a8773a` (make parallel reads opt-in).
- **840** (guest-clock workarounds): `3f3062e3` (enable timesync for Linux) ->
  `32eb92b5` (allow an explicit time-sync request from a guest) ->
  `6d800f98` (reduce `DELTA_SYNC` to 10 ms) -> `2f37b0a3` (build the init blob
  with the timesync feature when `TIMESYNC=1`).

Load-bearing details:

1. **Order matters for 865.** `6b24d0d2` without `08a8773a` leaves parallel reads
   permanently **on**, changing cang's block-device behaviour. Carry all three.
2. **840 postdates the ABI rewrite** - its head was force-pushed 2026-09-14/15,
   `a3d31822` is an ancestor, it touches no `src/vmm`/`polly`/`whp`/C-API code,
   and no adaptation is needed. The map's earlier "840 predates the rewrite"
   premise was stale and has been corrected.
3. **865 is opt-in and inert for us:** the new surface is
   `krun_block_device_set_parallel_reads(handle, bool)` (plus a weak typedef, an
   ffier entry and `BlockDevice::set_parallel_reads`), defaulting **false**, with
   no cargo feature or env knob. cang never calls it and this map wires no knobs,
   so only `802c9e1e`'s `Mutex<FormatAccess>` -> `RwLock` refactor is live.
4. **840 needs `TIMESYNC=1` to be non-inert in shipped prebuilts.** The host half
   (`3f3062e3`) is unconditional, but the guest half only exists when the init
   blob is built with the feature. The fork's `publish-cang-release.yml` did not
   pass it; that has been fixed in the rebased branch, together with assertions
   on `libkrun_init.{so*,pc,h}`.
5. **Which init runs matters:** under ABI 2 the guest init is the separate
   `libkrun_init.so`. If tickets 09/10 keep libkrun's default init, the
   `TIMESYNC=1` blob is what runs; if cang ships its own init, it must implement
   the time-sync request itself, which `cang-guest-init` does not do today.
6. Neither PR is observable in ticket 08's smokes without wiring a knob (out of
   scope), and 865's new declaration does not collide with the fork's
   `include/libkrun.h` re-additions.
